# Архитектура мобильного приложения

## Общая схема

Patrol System Mobile — Android-клиент монорепозитория. Приложение получает бизнес-состояние через
HTTP API, хранит защищённую сессию на устройстве, поддерживает локальные снимки активного обхода и
синхронизирует NFC-события после восстановления сети.

```text
Экраны Expo Router
        │
        ├── feature-компоненты и hooks
        │        ├── TanStack Query ── HTTP API
        │        ├── Zustand ───────── сессия и текущий магазин
        │        └── SQLite ────────── очередь и runtime-снимки
        │
        ├── системные адаптеры
        │        ├── NFC
        │        ├── геолокация
        │        ├── камера и файлы
        │        ├── уведомления
        │        └── защищённое хранилище
        │
        └── UI-kit и тема
```

Backend является источником истины для ролей, назначений, маршрутов, расписаний и состояния
обходов. Локальное состояние позволяет приложению продолжить ограниченный рабочий сценарий без
сети, но не заменяет серверную валидацию.

## Маршрутизация

Каталог `app` использует Expo Router. Файл `_layout.tsx` создаёт корневой стек, подключает
провайдер запросов, обработчик ошибок, системные сервисы и проверку доступа.

Корневой layout выполняет:

- восстановление сессии;
- перенаправление неавторизованного пользователя на экран входа;
- обязательный выбор магазина для сотрудника с несколькими назначениями;
- блокировку экранов, не разрешённых текущей роли;
- запуск менеджера офлайн-синхронизации;
- проверку серверной сессии;
- регистрацию push-уведомлений;
- актуализацию локального плана;
- проверку OTA-обновлений;
- глобальную обработку ошибок отображения.

Проверка маршрутов на клиенте предназначена для корректного интерфейса. Защиту данных всегда
обеспечивают guards и проверки области доступа на backend.

## Управление состоянием

### TanStack Query

Серверные данные загружаются и кэшируются через TanStack Query. Query key включает идентификаторы
магазина, сущности, фильтры, сортировку и строку поиска. Это исключает смешение выдачи разных
контекстов и обеспечивает повторную загрузку при изменении параметров.

Изменяющие операции инвалидируют связанные данные. Глобальный Query Client очищается при выходе,
чтобы данные предыдущего пользователя не оставались в памяти.

### Zustand

Глобальный auth store хранит:

- статус инициализации;
- access- и refresh-токены в памяти процесса;
- профиль и capabilities;
- выбранный магазин;
- действия входа, обновления профиля, выбора магазина и выхода.

Постоянное хранение токенов реализовано отдельно через SecureStore.

### SQLite

SQLite используется для данных, которым требуется пережить перезапуск процесса:

- очереди NFC-событий;
- очереди попыток пропуска точки;
- плана локальных уведомлений;
- снимка профиля для ограниченного холодного запуска без сети;
- снимков активного обхода, маршрута и NFC wait-state.

Очереди обхода содержат владельца `user_id`; выборки и обновления выполняются в контексте текущего
пользователя.

## UI-слой

Базовые элементы находятся в `src/ui`, а цвета, размеры, интервалы и радиусы — в `src/theme`.
Экраны собираются из общих компонентов для заголовков, полей, карточек, статусов, пустых состояний,
ошибок, фильтров и нижних панелей.

Сетевые списки различают первоначальную загрузку, ошибку без данных, пустое состояние, обновление
имеющегося содержимого и догрузку следующей страницы. Это предотвращает исчезновение уже
показанных данных во время фонового запроса.

## Общие контракты

Типы DTO и enum импортируются из `@patrol/shared` только как TypeScript-типы, если значение не
нужно во время выполнения. Это сохраняет единый контракт с backend и не включает NestJS-зависимости
в React Native bundle.

Точный состав endpoint и правила серверной авторизации поддерживаются в
[`docs/backend`](../../backend/README.md) и Swagger. Mobile-слой не создаёт собственную независимую
копию серверных контрактов.

## Обработка ошибок

HTTP-ошибки приводятся к единому формату `ApiError`. Известные доменные коды преобразуются в
понятные пользователю сообщения. Ошибки повторной авторизации, доступа и сервера передаются в
централизованный logger, а ожидаемые ошибки формы остаются частью пользовательского сценария.

Необработанная ошибка React render tree перехватывается Error Boundary. Приложение показывает
безопасный экран ошибки и отправляет диагностическое событие без токенов, ключей доступа, NFC UID,
ФИО и точных координат.
