# Данные, фотографии и отчёты

## HTTP-клиент

Все сетевые функции используют общий Axios client. Его `baseURL` берётся только из обязательной
переменной `EXPO_PUBLIC_API_BASE_URL`, завершающий слеш удаляется. Отсутствие переменной считается
ошибкой конфигурации и останавливает запуск некорректно собранного клиента.

Клиент добавляет Bearer token, применяет общий таймаут, преобразует ответы backend в `ApiError` и
координирует одну попытку silent refresh. API-функции возвращают `response.data`, не передавая
Axios response в UI-слой.

## Загрузка и кэширование

TanStack Query управляет серверным состоянием. Для обычных карточек применяются запросы по
идентификатору, а для больших списков — infinite queries с серверной пагинацией.

Поиск отправляется после debounce. Фильтры, сортировка и область магазина входят в query key.
Следующая страница добавляется только при наличии серверного `hasNextPage`; изменение фильтра
создаёт новую выборку с первой страницы.

При фоновой перезагрузке ранее полученные данные остаются на экране. Ошибка без данных, пустой
результат, обновление существующего списка и догрузка страницы отображаются разными состояниями.

Изменяющие операции инвалидируют только связанные домены. При смене пользователя весь Query Cache
очищается.

## Фотографии контрольных точек

Настройщик может выбрать изображение из галереи или сделать снимок камерой. Клиент проверяет
размер до отправки и формирует multipart-запрос. Backend дополнительно проверяет тип и размер,
ориентирует изображение по EXIF, уменьшает его и сохраняет в стандартизированном формате.

Фотография возвращается как идентификатор защищённого файла. Компонент `ProtectedImage` загружает
его через backend с access-токеном. Прямой публичный URL не создаётся. На экране обхода фотография
помогает сотруднику визуально определить текущую точку.

## Операционные отчёты

Сотрудник контроля создаёт отчёт в контексте выбранного магазина. Поддерживаются следующие
категории:

- фотоотчёт;
- утренний отчёт;
- отчёт о закрытии;
- воскресный отчёт;
- отопительный отчёт;
- эвакуационный отчёт.

Пользователь заполняет отчёт и выбирает фотографии на одном экране. При отправке backend создаёт
черновик, клиент последовательно загружает выбранные фотографии и затем отправляет отчёт.
Фотоотчёт требует хотя бы одного изображения; для остальных категорий фото необязательно.
Незавершённый после сетевой ошибки черновик можно повторно отправить или отменить.

Файлы загружаются до финальной отправки. Интерфейс остаётся единой формой, а клиент различает локально
выбранные и уже загруженные вложения, чтобы повторная попытка не дублировала файлы. Ошибка
отдельного файла не должна создавать ложное состояние успешно отправленного отчёта.

Проверяющий и администратор получают серверные контрольные представления отчётов. Изображения в
них также загружаются как защищённые файлы с текущим access-токеном.

## Анонимные обращения

Обращение содержит идентификатор магазина, категорию и текст. Клиент передаёт технический
идентификатор устройства, но не добавляет ФИО в payload. Backend отвечает за бизнес-анонимность,
безопасный audit и ограничение области просмотра.

Контролирующие роли могут открывать обращение и менять рабочий статус. UI не показывает IP,
device ID и другие технические признаки автора.

## Контрольные данные

История обходов, нарушения, магазины, сотрудники и отчёты загружаются через безопасные read model.
Для проверяющего область данных ограничивается назначенными магазинами на backend. Фильтр магазина
или сотрудника передаётся серверу и сохраняется при пагинации; клиент не выполняет фильтрацию
чужой полной выборки локально.

Историческая карточка обхода использует `routeSnapshot`. Названия, порядок и нормативы посещений
не заменяются текущей версией маршрута.

## Локальные данные

SQLite содержит только данные, необходимые для офлайн-сценария и системных напоминаний. Токены и
ключи доступа в SQLite не сохраняются. Содержимое базы считается внутренним кэшем устройства и не
является резервной копией серверных данных.

Файлы пользователя передаются backend после выбора. Приложение не поддерживает отдельный
публичный каталог изображений и не раскрывает защищённые file endpoint без авторизации.
