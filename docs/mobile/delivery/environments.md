# Окружения и конфигурация

## Назначение окружений

Мобильное приложение разделяет разработку, внутреннюю проверку и эксплуатацию. Каждое окружение
имеет собственный backend, EAS environment и канал обновлений.

| Окружение | Назначение | Backend | EAS channel | Артефакт |
|---|---|---|---|---|
| Development | Работа разработчика и диагностика | Локальный или изолированный тестовый | `development` | Development APK |
| Preview | Проверка на реальных устройствах и передача тестировщикам | Публичный тестовый | `preview` | APK внутреннего распространения |
| Production | Работа конечных пользователей | Стабильный публичный HTTPS API | `production` | AAB для Google Play |

Тестовая и production-среда не должны использовать одну базу данных, файловое хранилище и набор
пользователей. Демонстрационные seed-данные применяются только в development или изолированном
preview.

## Конфигурация mobile

Единственная обязательная прикладная переменная клиента:

```env
EXPO_PUBLIC_API_BASE_URL=https://patrol.example.ru/api/v1
```

Значение определяет backend для входа, данных, файлов и синхронизации. Префикс `EXPO_PUBLIC_`
означает, что переменная включается в JavaScript bundle и доступна пользователю. В ней нельзя
хранить секреты или служебные токены.

Локально переменная находится в `apps/mobile/.env`. Файл исключён из Git и EAS upload. Для
облачных сборок и OTA значение создаётся в Expo project settings отдельно для `development`,
`preview` и `production`.

Firebase-конфигурация передаётся EAS как file variable:

```text
GOOGLE_SERVICES_JSON
```

Она требуется на этапе разрешения `app.config.js` и нативной сборки. Для локального prebuild
используется `apps/mobile/google-services.json`.

## Конфигурация backend

Backend имеет независимый `.env`. В нём находятся параметры, которые никогда не должны попадать
в mobile:

- JWT access и refresh secrets;
- параметры PostgreSQL;
- пароль Redis;
- параметры файлового хранилища;
- настройки server push;
- служебные ключи интеграций;
- разрешённые web origins;
- режим Swagger и диагностики.

Изменение backend `.env` не требует пересборки APK, если публичный URL и API-контракт остаются
прежними.

## Development

Локальный backend доступен Android-эмулятору по специальному адресу хоста:

```env
EXPO_PUBLIC_API_BASE_URL=http://10.0.2.2:3000/api/v1
```

Физическое устройство использует LAN-адрес компьютера, USB port forwarding или HTTPS-туннель.
Development build подключается к Metro и содержит инструменты разработчика.

## Preview

Preview должен воспроизводить production-поведение клиента, но работать с тестовыми данными. Для
проверки другим человеком backend обязан быть доступен из интернета по HTTPS.

Временный tunnel URL допустим для короткой сессии. Он включается в bundle, поэтому прекращение
туннеля или изменение адреса делает API недоступным до выпуска обновления. Для регулярного
тестирования используется стабильный staging-домен.

Preview APK не требует Metro. Он подписан Android keystore проекта и распространяется через
ссылку EAS Internal Distribution либо внутренний канал организации.

## Production

Production URL должен:

- использовать HTTPS с публично доверенным сертификатом;
- быть доступным из Wi-Fi и мобильных сетей;
- иметь стабильный DNS;
- вести только на production backend;
- сохранять префикс API, ожидаемый клиентом;
- не зависеть от машины разработчика или временного туннеля.

Production environment EAS хранит только относящиеся к production значения. Доступ на изменение
этих переменных ограничивается владельцами релиза.

## Изменение адреса API

Адрес API читается при создании JavaScript bundle. Его изменение требует новой сборки либо
совместимого OTA-обновления с правильным EAS environment. Изменение переменной в Expo dashboard
само по себе уже установленное приложение не обновляет.

Перед переключением проверяется `/health`, TLS-сертификат и совместимость API. Старый backend
сохраняется доступным на время доставки обновления, если установленная база клиентов ещё может к
нему обращаться.

## Защита конфигурации

Файлы `.env`, Firebase service accounts, Android keystore и выгрузки credentials не коммитятся.
Примеры `.env.example` содержат имена всех обязательных параметров, но используют безопасные
плейсхолдеры.

Доступы передаются через роли соответствующих сервисов и корпоративное хранилище секретов. Личная
учётная запись разработчика не должна оставаться единственной точкой доступа к production.
