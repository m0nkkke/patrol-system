# Руководство мобильному разработчику по backend 0.3.0

Эта папка описывает, как Android-приложению работать с backend Patrol System в версии 0.3.0. Документы написаны с точки зрения mobile-разработчика: какие роли есть, какие endpoints вызывать, что хранить локально и какие экраны нужно реализовать по ТЗ.

## Документы

- [Устройство backend для mobile](backend-overview.md) - роли, авторизация, общие правила API, файлы, аудит.
- [API-потоки приложения](api-flows.md) - последовательности запросов для входа, выбора магазина, обхода, NFC, отчетов и anonymous.
- [Чеклист ТЗ 0.3.0 для mobile](implementation-checklist.md) - что нужно реализовать в приложении и что уже поддерживает backend.
- [Backend: нормативы маршрута и двухфазный скан точки](../../backend/modules/route-timing-and-point-visits.md) - полный backend-контракт новой логики обхода.

## Главная идея

Backend 0.3.0 уже уходит от старой модели `employee / manager / admin` и использует роли из нового ТЗ:

- `security_guard` - СК, проходит обходы, отправляет отчеты и anonymous appeal;
- `route_setter` - универсальный Настройщик;
- `local_route_setter` - локальный настройщик ТТ;
- `inspector` - Проверяющий;
- `admin` - Администратор.

Mobile-клиент должен строить интерфейс не по старым ролям, а по роли и capabilities из `GET /api/v1/mobile/me`.
