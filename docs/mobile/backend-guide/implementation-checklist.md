# Чеклист ТЗ 0.3.0 для mobile

## Авторизация и роли

- Реализовать обычный вход через `POST /api/v1/auth/login`.
- При `AUTH_ACTOR_FULL_NAME_REQUIRED` показать второй шаг входа универсального Настройщика.
- После ввода ФИО вызвать `POST /api/v1/auth/universal-route-setter/login` с тем же ключом и `deviceId`.
- Для универсального Настройщика сделать обязательный ввод ФИО при каждом входе.
- Сохранять `authorizationId` и `authorizationFullName` локально для отображения текущей сессии, если нужно.
- После входа всегда вызывать `GET /api/v1/mobile/me`.
- Перестроить UI со старых ролей `employee / manager / admin` на роли `security_guard / route_setter / local_route_setter / inspector / admin`.

## Рабочее место СК

- После входа СК показывать выбор магазина из `GET /api/v1/mobile/shops`.
- Не полагаться только на `user.shopId`.
- Добавить разделы СК:
  - обходы;
  - отчеты;
  - график;
  - anonymous.
- Хранить текущий выбранный `shopId` как контекст мобильной сессии.

## Обходы и NFC

- Поддержать несколько маршрутов на магазин.
- При старте обхода передавать `shopId`, а при необходимости `routeId` и `scheduleId`.
- Показывать категорию маршрута: `internal` или `external`.
- Показывать период обхода: `morning`, `noon`, `evening`.
- Учитывать `earlyStartMinutes`: обход может быть доступен раньше планового окна.
- После старта обхода автоматически включать foreground NFC listening.
- Использовать `GET /mobile/patrols/:id/nfc-wait-state` или `GET /mobile/patrols/active/nfc-wait-state`.
- Не требовать отдельную кнопку сканирования NFC в основном сценарии обхода.
- Поддержать двухфазное посещение точки: первый скан `arrive`, настраиваемая блокировка `0-120` секунд, повторный скан `depart`.
- Брать выдержку из `pointDwellSeconds`, не прошивать её в приложении; при `0` сразу ожидать повторный скан `depart`.
- Показывать таймер `lockedUntil` после первого скана точки.
- Не считать точку пройденной после `arrive`; точка завершена только после успешного `depart`.
- При `depart` ожидать ту же NFC-метку, что была использована для `arrive`.
- При скане не той будущей точки отправлять missed-point attempt.
- Сохранять NFC-события локально и синхронизировать через offline queue.
- Не рассчитывать норматив маршрута на устройстве: норматив, пороги и триггеры рассчитывает backend по истории за 14 дней.
- Обрабатывать триггеры backend: не выполнен обход, отхождение от графика, слишком быстро, подозрительно быстро, слишком долго, слишком короткое пребывание на точке.

## Фото

- Для Настройщика редактировать название и описание точки через `PATCH /api/v1/patrol-points/:id`.
- Архивировать точку через `DELETE /api/v1/patrol-points/:id` и восстанавливать через `POST /api/v1/patrol-points/:id/restore`.
- Не передавать в общий `PATCH` поля `sortOrder`, `shopId` или `nfcTagId`; порядок и NFC изменяются специализированными сценариями.

- Показывать фото контрольной точки, если есть `photoFileId`.
- Загружать защищенные файлы через `GET /api/v1/files/:id`.
- Для отчетов поддержать прикрепление фото.
- Перед загрузкой фото сжимать на клиенте, если это согласовано с текущей mobile-архитектурой. Backend также нормализует изображения.

## Операционные отчеты

- Реализовать список доступных типов отчетов:
  - фотоотчет;
  - утренний;
  - закрытие;
  - воскресный;
  - отопительный;
  - эвакуационный.
- Реализовать создание черновика отчета.
- Реализовать прикрепление фото к отчету.
- Реализовать отправку отчета.
- Реализовать отмену черновика.
- Формы полей сделать конфигурируемыми или легко расширяемыми, потому что состав отчетов уточняется заказчиком.

## График и локальные напоминания

- Загружать расписания по выбранному магазину.
- Строить локальный график СК.
- Создавать локальные уведомления заранее, чтобы они работали без сети.
- Планировать их средствами ОС как локальные уведомления с точным временем, а не ждать push от backend; запросить необходимые Android-разрешения и корректно обработать их отсутствие.
- При обновлении расписаний пересоздавать локальные уведомления.
- Учитывать timezone магазина при отображении времени.

## Конструктор Настройщика

- Для `route_setter` и `local_route_setter` дать конструктор маршрута из уже зарегистрированных точек.
- Передавать порядок через `patrolPointIds`, а индивидуальные выдержки через `pointSettings`.
- Давать выбор категории `internal` или `external`.
- Давать создание и изменение расписаний с периодом, днями недели, временем и ранним стартом.
- Локальному настройщику показывать только назначенные магазины; backend дополнительно проверяет эту область доступа.
- Для временного режима, включая пожароопасный период, позволить собрать отдельный маршрут и набор расписаний, затем переключать активность обычного и временного набора.

## Anonymous

- Добавить экран "Анонимно" для роли `security_guard`.
- Отправлять обращения через `POST /api/v1/mobile/anonymous`.
- Требовать выбранный `shopId`.
- Не показывать обращение как персонально подписанное.
- Категории: `message`, `complaint`, `safety`, `other`.

## Push

- После входа регистрировать Expo push token на backend.
- Повторять регистрацию при смене push token, переустановке приложения или смене deviceId.
- По `data.type`, `shopId`, `patrolId`, `incidentId` открывать нужный экран.

## Ошибки

- Отображать доменные ошибки по `code`.
- Не завязывать логику на текст `message`.
- При `401` делать один refresh и повтор исходного запроса.
- При неуспешном refresh очищать локальную сессию.

## Что пока не нужно делать в mobile

- Не реализовывать web-панель руководства в mobile.
- Не раскрывать audit log в mobile-интерфейсе СК.
- Не использовать Excel/CSV как транспорт данных между mobile и backend.
- Не прошивать NFC-метки: приложение читает аппаратный UID и отправляет его backend.
