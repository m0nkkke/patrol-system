# Web-панель

Web-панель находится в `apps/web`. В версии 0.3.0 доступны рабочие разделы Проверяющего, Администратора, Настройщика и Локального настройщика. Сотрудник контроля проходит обходы через мобильное приложение. Панель включает:

- вход по существующему ключу доступа;
- проверку роли через `GET /api/v1/auth/me`;
- защищенную оболочку приложения;
- список доступных Проверяющему магазинов;
- сводку магазина за 14 дней;
- последние обходы, инциденты, отчеты и ответственных сотрудников;
- раздел контрольных инцидентов с фильтрами, пагинацией и CSV/XLSX-выгрузкой;
- карточку расследования с маршрутом, таймингами, хронологией и NFC-контекстом;
- историю обходов с фильтрами по магазину, сотруднику, маршруту, статусу и датам;
- карточку обхода с нормативом маршрута, посещениями контрольных точек и парами NFC-сканов «прибыл/ушел»;
- операционные отчеты шести типов с фильтрами, CSV/XLSX-выгрузкой и просмотром фотографий.

## Обновление панели 07.09.2026

- Современная адаптивная оболочка: увеличенная типографика, карточки показателей, активная навигация и фильтры без горизонтального переполнения страницы. На телефоне показатели располагаются в две колонки.
- `/users`: список сотрудников, поиск, пагинация, переход к обходам сотрудника. Проверяющий создаёт только СК и только в назначенных магазинах. Администратор меняет роли, назначения, блокировку и ключ доступа. Собственную блокировку и замену ключа UI исключает.
- `/setup`: параметры и создание магазинов (admin); создание/редактирование маршрутов, изменение порядка точек и выдержки 0–120 секунд, история версий, архивирование/восстановление; создание точки вместе с NFC одним запросом; графики с днями недели, периодом и ранним стартом. Проверяющий видит конфигурацию без права редактирования. Настройщикам доступен только этот раздел; локальный настройщик ограничен назначенными магазинами сервером.
- Универсальный ключ настройщика требует ввода ФИО и использует отдельный endpoint авторизации.
- `/administration`: архив бизнес-объектов, восстановление и журнал действий с поиском, пагинацией и CSV/XLSX. Только admin.
- Кеш запросов очищается при входе, выходе и истечении сессии. Ответы старой сессии отклоняются; запоздалый refresh не восстанавливает её и не перезаписывает новую.
- Фильтры инцидентов, обходов и отчётов сохраняются в URL. Данные перечитываются раз в минуту и при возврате фокуса.
- Общие контрольные списки и управленческие периоды используют UTC; карточка магазина и настройки расписания — timezone магазина. Фото-просмотр удерживает фокус, закрывается Escape и возвращает фокус к исходной кнопке.
- Карточка обхода показывает сохранённый маршрут, включая выдержку. Порядок и названия исторических посещений берутся из снимка, если он существует.
- Management API переведён на `schemaVersion: "2.0"`: `registeredPatrols`, согласованный знаменатель выполнения, состояние `no_data`. Это показатели зарегистрированных обходов; неначатые окна расписания пока не учитываются. Полный план-факт требует исторического реестра occurrence-ов.

Полные формы и обязательные поля шаблонов операционных отчётов остаются отдельной задачей после согласования их семантики. Production cookie-сессия остаётся требованием [security.md](security.md).

Браузерная регрессия: запустить Vite и отдельный Chrome с remote debugging port 9229, затем `node scripts/web-panel-smoke.cjs` (Node 22). Скрипт перехватывает API и использует демонстрационные данные; это проверка UI, а не рабочей базы. Снимки и результаты сохраняются в `%TEMP%/patrol-web-panel-smoke`.

## Инциденты

Раздел доступен по адресу `/incidents`. Проверяющий видит только инциденты назначенных ему магазинов, администратор видит все доступные данные.

Поддерживаются фильтры по магазину, критичности, типу, диапазону дат и строке поиска. Выбранный инцидент имеет отдельный URL `/incidents/:id`, поэтому ссылку на расследование можно открыть напрямую. CSV/XLSX-выгрузки используют те же фильтры и ограничения доступа, что и экранный список.

## История обходов

Раздел доступен по адресу `/patrols`, карточка конкретного обхода — по адресу `/patrols/:id`. После выбора магазина становятся доступны точные фильтры по назначенным сотрудникам и маршрутам этого магазина.

Карточка показывает плановое и фактическое время, норматив по двухнедельной выборке, прогресс маршрута, посещения контрольных точек, входной и выходной NFC-сканы, позднюю синхронизацию, связанные инциденты и отчеты.

## Операционные отчеты

Раздел доступен по адресу `/reports`, карточка конкретного отчета — по адресу `/reports/:id`. Поддерживаются все шесть типов ТЗ 0.3.0: фотоотчет, утренний, закрытие, воскресный, отопительный и эвакуационный.

Фильтры работают по магазину, сотруднику, типу, статусу, периоду и диапазону дат. Карточка показывает структурированные поля, комментарий, связь с обходом и защищенную фотогалерею. Файлы загружаются авторизованным API-запросом и не публикуются как статические URL.

## Управленческая отчетность

Раздел доступен администратору по адресу `/management`. Проверяющий не видит пункт меню и при прямом переходе возвращается к списку доступных магазинов. Backend дополнительно защищает все management endpoints ролью `admin`.

Экран содержит:

- агрегированные показатели выполнения, своевременности и обходов без замечаний;
- среднюю длительность обхода и число магазинов в зеленой зоне;
- динамику по дням, неделям и месяцам;
- разрез по внутренним/внешним маршрутам и периодам обхода;
- scorecards магазинов с сортировкой и переходом в контрольную карточку;
- CSV/XLSX-выгрузки сводки, динамики, разреза и scorecards с учетом текущих фильтров.

Управленческое представление не содержит ФИО сотрудников, фотографий, комментариев и сырой ленты NFC-событий. Для расследования администратор переходит в контрольные разделы.

## Локальный запуск

Сначала запустить backend на `http://127.0.0.1:3000`, затем из корня проекта:

```powershell
npm run web:dev
```

Панель будет доступна по адресу `http://127.0.0.1:5173`.

Для проверки на сценарных данных:

```powershell
npm run backend:seed:scenarios
```

Учетная запись Проверяющего:

- ключ: `MNGR-IRKK-0001`;
- назначенный магазин: `Demo Irkutsk`.

Учетная запись Администратора для управленческой отчетности:

- ключ: `ADMN-DEMO-0001`;
- доступ: все магазины и раздел `/management`.

API URL задается через `VITE_API_URL`. Пример находится в `apps/web/.env.example`.

## Production blocker

Текущая development-реализация временно хранит access/refresh токены в `sessionStorage`. Выпуск web-панели в production с этой схемой запрещен.

Обязательные изменения перечислены в [Безопасность web-сессии](security.md).
