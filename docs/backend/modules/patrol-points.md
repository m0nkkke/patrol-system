# Модуль Patrol Points

Модуль `patrol-points` управляет физическими NFC-метками и контрольными точками обхода внутри магазина. Удаление контрольной точки является обратимым архивированием: исторические обходы и NFC-события сохраняются.

## Endpoints

- `POST /api/v1/patrol-points/nfc-tags` — регистрирует NFC-метку.
- `POST /api/v1/patrol-points` — создаёт контрольную точку и опционально связывает её с NFC-меткой.
- `POST /api/v1/patrol-points/with-nfc` — атомарно создаёт отдельную точку и регистрирует отсканированный UID.
- `GET /api/v1/patrol-points/shop/:shopId` — возвращает активные точки магазина.
- `GET /api/v1/patrol-points/shop/:shopId/archived` — возвращает архивные точки магазина.
- `GET /api/v1/patrol-points/:id` — возвращает активную контрольную точку.
- `PATCH /api/v1/patrol-points/:id` — изменяет название и описание.
- `DELETE /api/v1/patrol-points/:id` — архивирует контрольную точку.
- `POST /api/v1/patrol-points/:id/restore` — восстанавливает контрольную точку.
- `POST /api/v1/patrol-points/:id/photo` — загружает и сжимает фото контрольной точки.
- `POST /api/v1/patrol-points/:id/replace-nfc` — заменяет NFC-метку с сохранением истории.

`PATCH` принимает частичное тело:

```json
{
  "name": "Электрощитовая",
  "description": "Проверить доступ и состояние щита"
}
```

Для удаления описания нужно передать `description: null`. Магазин и порядок точки этим endpoint
не изменяются: порядок задается через `patrol_route_points`, а NFC управляется сценариями
регистрации и замены метки.

## Доступ

Все endpoints требуют `Authorization: Bearer <accessToken>`.

- создание, изменение, архивирование, восстановление, фото и замена NFC доступны `admin`, `route_setter`, `local_route_setter`;
- чтение активных точек доступно также `inspector`;
- `local_route_setter` и `inspector` ограничены назначенными магазинами;
- `route_setter` и `admin` могут работать со всеми магазинами;
- `inspector` не может создавать или изменять контрольные точки.

## Архивирование

`DELETE` устанавливает `is_active=false` и `deleted_at`. Физическое удаление не выполняется, поэтому ссылки из истории обходов остаются действительными.

Точку нельзя архивировать, пока она входит хотя бы в один активный маршрут. Backend возвращает ошибку `PATROL_POINT_IN_ACTIVE_ROUTE`; перед архивированием точку нужно удалить из маршрута или деактивировать маршрут.

Восстановление возвращает `is_active=true` и очищает `deleted_at`. Если сохраненная NFC-метка уже
назначена другой активной точке, точка восстанавливается без NFC-привязки. Повторная привязка
выполняется отдельным NFC-сценарием.

Стабильные доменные коды CRUD:

- `PATROL_POINT_NOT_FOUND`;
- `PATROL_POINT_FORBIDDEN`;
- `PATROL_POINT_ALREADY_ARCHIVED`;
- `PATROL_POINT_NOT_ARCHIVED`;
- `PATROL_POINT_IN_ACTIVE_ROUTE`.

Общий административный endpoint `/api/v1/archive/patrol-points/:id` делегирует операцию этому же сервису и не обходит проверки маршрутов и NFC.

## NFC-правила

- UID нормализуется в нижний регистр перед записью и сравнением.
- NFC-метка может быть не привязана к точке, но прохождение точки без активной метки невозможно.
- К точке можно привязать только существующую активную метку.
- Одна активная NFC-метка не может быть одновременно назначена двум активным точкам.
- При замене старая метка деактивируется, а запись сохраняется в `nfc_tag_replacements`.

## Фото

Фото хранится через `file_assets` и общий storage-контракт. Backend сжимает изображение перед сохранением. Локальный настройщик может изменять фото только у точек назначенного ему магазина.

## Атомарная регистрация отдельной точки

Используйте `POST /api/v1/patrol-points/with-nfc` с общим DTO `CreatePatrolPointWithNfcDto`:

```json
{
  "shopId": "00000000-0000-4000-8000-000000000001",
  "name": "Электрощитовая",
  "description": "Проверить доступ",
  "uid": "04A1B2C3D4E5F6",
  "sortOrder": 0
}
```

Обязательны `shopId`, `name`, `uid`; необязательны `description`, `sortOrder`, `isActive`, `payload`.
UID нормализуется в нижний регистр. `registeredBy` берётся из авторизованного пользователя;
поля `registeredBy` и `nfcTagId` в запросе не допускаются. Роли — `admin`, `route_setter`,
`local_route_setter`; сервис проверяет назначение магазина до записи.

Ответ `201` — созданная точка с `nfcTagId` и вложенным `nfcTag`. Метка и точка сохраняются
в одной транзакции: при сбое точки новая метка откатывается. Уже зарегистрированный UID,
в том числе неиспользуемый или неактивный, возвращает `NFC_UID_ALREADY_REGISTERED` (400).
Уникальность обеспечивается БД и при параллельных запросах. Привязка ранее зарегистрированной
активной свободной метки остаётся доступна через обычное создание точки с `nfcTagId`.
