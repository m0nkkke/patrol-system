# Archive

Модуль архива дает единый backend API для просмотра, архивирования и восстановления объектов. В версии 0.3.0 это reversible archive: данные не удаляются физически, а переводятся в архивное состояние.

## Endpoints

Все endpoints доступны только роли `admin`.

- `GET /api/v1/archive/:resourceType` - список архивных объектов;
- `POST /api/v1/archive/:resourceType/:id` - архивировать объект;
- `POST /api/v1/archive/:resourceType/:id/restore` - восстановить объект.

Поддерживаемые `resourceType`:

- `shops`;
- `users`;
- `patrol-points`;
- `nfc-tags`;
- `patrol-routes`;
- `file-assets`.

## Формат Ответа

```json
{
  "items": [
    {
      "resourceType": "shops",
      "id": "00000000-0000-4000-8000-000000000001",
      "displayName": "Shop 1",
      "archived": true,
      "archiveReason": "soft_deleted",
      "archivedAt": "2026-08-18T10:00:00.000Z",
      "data": {}
    }
  ],
  "page": 1,
  "limit": 20,
  "total": 1
}
```

`archiveReason`:

- `soft_deleted` - объект скрыт через `deleted_at`;
- `inactive` - объект переведен в `is_active=false`;
- `null` - объект уже восстановлен.

## Поведение По Типам

`shops`, `users`, `patrol-points`, `patrol-routes` и `file-assets` архивируются через `deleted_at`.

`shops`, `users`, `patrol-points` и `patrol-routes` дополнительно получают `is_active=false`, чтобы объект не участвовал в рабочих сценариях даже при прямой выборке с `withDeleted`.

Для контрольных точек предпочтительны специализированные endpoints `DELETE /api/v1/patrol-points/:id` и `POST /api/v1/patrol-points/:id/restore`. Общий archive endpoint делегирует операции модулю `patrol-points`, поэтому сохраняются проверки активных маршрутов и прав на магазин. При занятой NFC-метке точка восстанавливается без привязки.

`nfc-tags` архивируются через `is_active=false`. Для маршрута изменение `is_active` является
обратимым включением или отключением, а архивирование дополнительно устанавливает `deleted_at`.
Архивировать маршрут, связанный с активным расписанием, нельзя.

Восстановление возвращает объект в рабочее состояние:

- снимает `deleted_at`, если он есть;
- выставляет `is_active=true`, если у объекта есть такой флаг.

## Файлы

Архивирование `file-assets` не удаляет физический файл из локального или объектного хранилища. Это важно для восстановления фото отчетов и контрольных точек.

Физическое удаление файлов должно быть отдельной будущей операцией `purge` с retention-политикой, проверкой ссылок и отдельным audit-событием.

## Ограничения Версии 0.3.0

- Архив отчетов и инцидентов пока не выделен в отдельное состояние: отчеты используют `status`, инциденты остаются первичными фактами расследования.
- Массовое восстановление не добавлено.
- Восстановление не пересчитывает производные витрины; текущие management/control endpoints строятся из актуальных данных при запросе.
- Для пользователей архивирование через центральный endpoint не делает отдельной бизнес-логики кроме `is_active=false`; успешное действие попадет в audit log через глобальный interceptor.
