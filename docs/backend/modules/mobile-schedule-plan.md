# Mobile Schedule Plan

Модульный контракт для графика СК и локальных напоминаний в мобильном приложении.

## Назначение

Backend отдает мобильному приложению не сырые `weekdays/startTime/endTime`, а уже рассчитанные будущие occurrence-ы обходов. Мобильное приложение сохраняет этот план локально и ставит локальные уведомления, которые должны сработать без сети.

## Endpoint

```http
GET /api/v1/mobile/schedule-plan?days=7
Authorization: Bearer <accessToken>
```

Для одного магазина:

```http
GET /api/v1/mobile/schedule-plan?shopId=00000000-0000-4000-8000-000000000001&days=14
Authorization: Bearer <accessToken>
```

Доступ: `security_guard`.

Параметры:

- `days` - горизонт планирования от 1 до 31 дня, по умолчанию 7;
- `shopId` - необязательный ID магазина; если не передан, backend строит план по всем активным назначенным магазинам СК.

## Response

```json
{
  "generatedAt": "2026-08-18T13:00:00.000Z",
  "days": 7,
  "items": [
    {
      "scheduleId": "00000000-0000-4000-8000-000000000010",
      "shopId": "00000000-0000-4000-8000-000000000001",
      "shopName": "Shop 1",
      "routeId": "00000000-0000-4000-8000-000000000020",
      "scheduleName": "Утренний обход",
      "period": "morning",
      "plannedStartAt": "2026-08-19T03:00:00.000Z",
      "availableFrom": "2026-08-19T02:30:00.000Z",
      "dueAt": "2026-08-19T04:00:00.000Z",
      "notificationAt": "2026-08-19T02:30:00.000Z",
      "weekday": 3,
      "timezone": "Asia/Krasnoyarsk"
    }
  ]
}
```

## Правила Расчета

- Время расписания хранится как локальное время магазина.
- Backend рассчитывает UTC-времена через `shops.timezone`.
- `plannedStartAt` соответствует `startTime`.
- `availableFrom` соответствует `startTime - earlyStartMinutes`.
- `dueAt` соответствует `endTime`.
- `notificationAt` в версии 0.3.0 равно `availableFrom`.
- Прошедшие occurrence-ы не возвращаются.
- Неактивные расписания не возвращаются.
- Если `shopId` передан, backend проверяет, что магазин назначен текущему СК.

## Ответственность Mobile

Mobile-клиент должен:

- вызывать endpoint после входа и при успешной синхронизации;
- сохранять план локально;
- создавать локальные уведомления по `notificationAt`;
- планировать уведомления на устройстве по абсолютному времени как локальный «будильник», не зависящий от сети и push-доставки;
- пересоздавать уведомления при получении нового плана;
- не рассчитывать timezone/weekday самостоятельно, кроме отображения пользователю.

## Ограничения Версии 0.3.0

- Нет отдельных шаблонов текста уведомлений на backend.
- Нет пользовательской настройки “напомнить за N минут до доступности”.
- Нет server-side календаря смен конкретного СК; план строится по активным расписаниям назначенных магазинов.
