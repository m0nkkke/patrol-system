# Модуль Patrol Schedules

Модуль `patrol-schedules` управляет повторяющимися временными окнами обходов магазина. Расписание является шаблоном: оно определяет дни недели и допустимое время старта, а конкретный обход создаётся сотрудником в мобильном приложении.

## Модель данных

Таблица `patrol_schedules` содержит:

- `shop_id` — магазин, для которого действует расписание;
- `route_id` — маршрут, к которому привязано расписание; пока необязателен для переходного состояния 0.3.0;
- `name` — понятное название окна;
- `period` — структурированный период обхода: `morning`, `noon` или `evening`;
- `weekdays` — дни недели от `1` (понедельник) до `7` (воскресенье);
- `start_time` — плановое начало обхода;
- `end_time` — конец окна и дедлайн завершения обхода;
- `early_start_minutes` — на сколько минут раньше `start_time` можно начать обход;
- `is_active` — можно ли использовать расписание.

Время хранится без таймзоны и интерпретируется в `shops.timezone`. Ночные окна через границу суток пока не поддерживаются: `endTime` должен быть позже `startTime` в пределах одного календарного дня. Окно доступности начинается в `startTime - earlyStartMinutes`, но дедлайн обхода остается равным `endTime`.

## Эндпоинты управления

Все эндпоинты требуют Bearer JWT.

- `POST /api/v1/patrol-schedules` — создать расписание; роли `admin`, `route_setter`, `local_route_setter`.
- `GET /api/v1/patrol-schedules/shop/:shopId` — получить все расписания магазина; роли `admin`, `route_setter`, `local_route_setter`, `inspector`.
- `GET /api/v1/patrol-schedules/:id` — получить расписание; роли `admin`, `route_setter`, `local_route_setter`, `inspector`.
- `PATCH /api/v1/patrol-schedules/:id` — изменить расписание; роли `admin`, `route_setter`, `local_route_setter`.
- `DELETE /api/v1/patrol-schedules/:id` — деактивировать расписание без удаления истории; роли `admin`, `route_setter`, `local_route_setter`.

Если расписание содержит `routeId`, backend проверяет, что маршрут активен и принадлежит тому же магазину.

Локальный настройщик ТТ может работать только с расписаниями своего магазина. Администратор и настройщик могут управлять расписаниями любого магазина.

Пример создания:

```json
{
  "shopId": "00000000-0000-4000-8000-0000000000aa",
  "routeId": "00000000-0000-4000-8000-0000000000bb",
  "name": "Вечерний обход",
  "period": "evening",
  "weekdays": [1, 2, 3, 4, 5, 6, 7],
  "startTime": "20:00",
  "endTime": "21:00",
  "earlyStartMinutes": 30
}
```

Активные окна одного магазина не могут пересекаться в общие дни недели. При проверке пересечений учитывается ранний старт: фактическое окно считается от `startTime - earlyStartMinutes` до `endTime`. При пересечении backend возвращает `PATROL_SCHEDULE_OVERLAP`.

## Использование мобильным приложением

- `GET /api/v1/mobile/shops/:shopId/patrol-schedules/available` возвращает активные расписания, доступные сотруднику прямо сейчас по локальному времени выбранного назначенного магазина. Если по расписанию в текущем окне уже есть неотмененный обход, оно исключается из списка.
- Каждый элемент ответа содержит `period`, `earlyStartMinutes` и дополнительно `dueAt` в UTC для доступного окна.
- `POST /api/v1/mobile/patrols/start` принимает необязательный `scheduleId`.
- Если `scheduleId` передан, backend повторно проверяет магазин, активность, день недели и временное окно с учетом `earlyStartMinutes`, затем сам рассчитывает `patrols.due_at`.
- Раз в минуту backend переводит незавершённые обходы с истёкшим `due_at` в статус `overdue`.
- Статус `overdue` не блокирует маршрут: сотрудник может продолжать сканирование и завершить обход, а факт опоздания остаётся доступен для контроля.
- Если `scheduleId` не передан, создаётся внеплановый обход с `schedule_id = NULL` и `due_at = NULL`.

Расписание не создаёт `patrol` заранее. В текущей модели у расписания нет назначенного сотрудника, а `patrols.employee_id` обязателен, поэтому конкретный обход появляется в момент старта сотрудником.

## Доменные ошибки

- `PATROL_SCHEDULE_INVALID_WINDOW` — конец окна не позже начала.
- `PATROL_SCHEDULE_OVERLAP` — активное окно пересекается с другим расписанием.
- `PATROL_SCHEDULE_WRONG_SHOP` — расписание принадлежит другому магазину.
- `PATROL_SCHEDULE_INACTIVE` — расписание деактивировано.
- `PATROL_SCHEDULE_OUTSIDE_WINDOW` — попытка старта вне разрешённого дня или времени.
- `PATROL_SCHEDULE_FORBIDDEN` — пользователь не имеет доступа к магазину.
- `PATROL_SCHEDULE_DUE_AT_MANAGED` — клиент одновременно передал `scheduleId` и собственный `dueAt`.
